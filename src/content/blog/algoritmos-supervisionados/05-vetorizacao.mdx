Nos posts anteriores, vimos a seguinte fórmula da Regressão Linear Múltipla:

$$
f_{w,b}(x) = \vec{w} \cdot \vec{x} + b
$$

Matematicamente isso é perfeito. Mas, computacionalmente, isso pode ser um pesadelo se tivermos que resolver termo a termo milhões de dados (tipo quando $n = 5.000.000$).

Se você já programou em alguma linguagem de programação, sua intuição mandaria utilizar um loop ```for``` para percorrer todos os dados e somá-los. Porém, em Python, para Machine Learning, evitamos utilizá-lo.

### Por que evitar loops em Python?
Python é uma linguagem interpretada e dinâmica. Ou seja, cada iteração passa pelo interpretador para acessar os objetos e executar as operações, podendo criar novos objetos e alocar memória. Isso acaba gerando uma sobrecarga enorme principalmente se houver uma enorme quantidade de dados a serem processados pelo loop.

## Introdução a Vetorização (NumPy)
Então se utilizar loops não é a melhor abordagem para esse caso, temos uma alternativa perfeita para essa situação que é justamente a **Vetorização**. A vetorização permite que o nosso computador execute operações em conjuntos de dados inteiros de uma só vez. Isso delega os cálculos a rotinas compiladas e otimizadas, que podem aproveitar instruções SIMD (Single Instruction, Multiple Data) e outros recursos do hardware.

Para usar isso em Python, utilizamos a biblioteca **NumPy**.

### A comparação: Loop vs Vetorização
Se você ainda não acredita em mim, te provarei agora que o loop ```for``` é mais lento que a vetorização! (e também aprenderá como utilizar a vetorização). Vamos, portanto, simular o cálculo do modelo $\mathbf{w} \cdot \mathbf{x}$ (Produto Escalar).

#### A implementação com loop (lenta)
Começaremos com a implementação do loop ```for```. Vamos percorrer cada elemento dos vetores 'w' e 'x' multiplicando-os e somar tudo.

```python
import time

# 1 milhão de features como dados simulados
w = [i * 0.0001 for i in range(1000000)]
x = [i * 0.0001 for i in range(1000000)]

def produto_escalar_loop(w, x):
  resultado = 0
  for i in range(len(w)):
    resultado += x[i] * w[i] # Produto Escalar
  return resultado

start = time.time()
resultado_final = produto_escalar_loop(w, x)
end = time.time()

print(f"Tempo com loop: {end - start:.5f} segundos.")
```

#### A implementação vetorizada (rápida)
Aqui temos a nossa implementação visada em performance. Veja que o código também fica menor e mais limpo utilizando o método de vetorização.

```python
import numpy as np
import time

w = [i * 0.0001 for i in range(1000000)]
x = [i * 0.0001 for i in range(1000000)]

# A conversão para array é necessária para o NumPy 
# trabalhar
w_np = np.array(w)
x_np = np.array(x)

start = time.time()
resultado = np.dot(w_np, x_np) # Produto Escalar
end = time.time()

print(f"Tempo com vetorização: {end - start:.5f} segundos.")
```

##### **📊 Resultado da Comparação**

| Método | Tempo de Execução | Performance |
| :--- | :--- | :--- |
| Loop `for` (Python) | 0.05918s | 1x (Base) |
| **Vetorização (NumPy)** | **0.00186s** | **~32x mais rápido** |

Nessa medição, a implementação vetorizada foi aproximadamente 32x mais rápida. Esse ganho varia com o ambiente, o tamanho dos dados e a biblioteca utilizada; não é uma garantia para qualquer operação.

## Conexão com a Matemática 
Lembra da fórmula matemática que vimos no Blog passado que envolvia o Produto Escalar ($f_{\mathbf{w},b}(\mathbf{x}) = \mathbf{w} \cdot \mathbf{x} + b $)? A vetorização permite traduzir essa matemática diretamente para o código. Em vez de escrevermos 10 linhas de loop, podemos simplesmente escrever:

```python
f = np.dot(w, x) + b
```

Dessa forma o código ficará muito mais limpo, organizado e rápido.

## Por trás dos bastidores
É muito interessante como algoritmos com e sem vetorização, apesar de terem o mesmo propósito, apresentam velocidades de execução tão distintas. Para podermos entender melhor como isso é possível, precisamos entender como ambos os algoritmos funcionam computacionalmente.

### Sem vetorização

Como vimos anteriormente, na abordagem sem vetorização utilizamos o ```for``` loop para percorrer os dados. A questão é que o processador executa uma iteração por vez, sequencialmente.

```python
import time

def dot_product_nao_vetorizado(w, x):
  f = 0
  # O loop impõe uma ordem sequencial rígida
  for j in range(len(w)):
      # O processador precisa buscar w[j] e x[j], 
      # multiplicar, somar a 'f' e
      # só então passar para o próximo j.
      f = f + w[j] * x[j] 
  return f
```

A linha do tempo seria basicamente:
* No tempo $t_{0}$, o computador busca o valor $w_{0}$ e $x_{0}$, multiplica e soma ao acumulador $f$.
* Somente após terminar essa conta, ele avança para o próximo tempo $t_{1}$, para processar o índice 1.
* Isso se repete até o último elemento ($t_{n}$).

Ou seja, para o vetor de 1.000.000 de elementos, o loop executa 1.000.000 de iterações dessa conta, o que não significa 1.000.000 de ciclos de CPU. Meio demorado, hein.

### Com vetorização

Ao usarmos ```np.dot(w, x)```, essa lógica muda completamente. diferente do loop ```for```, onde o Python processa um dado por vez, a vetorização aproveita o hardware moderno para processar blocos inteiros de dados de uma só vez.

```python
import numpy as np

# Abordagem COM vetorização 
# (SIMD: Single Instruction, Multiple Data)
def dot_product_vetorizado(w, x):
    # O Python delega tudo 
    # para o backend em C/Assembly otimizado
    return np.dot(w, x)
```

No código acima, o NumPy delega o cálculo a rotinas otimizadas, reduzindo a sobrecarga do loop em Python. Elas podem processar blocos de dados com SIMD e, dependendo da biblioteca e da operação, usar múltiplas threads. Isso não significa que todas as multiplicações acontecem ao mesmo tempo.
